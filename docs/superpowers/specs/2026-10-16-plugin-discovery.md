# 插件自动发现与 OCR 接入

用户于 2026-10-16 批准：整个插件仓库自动发现，不再手工维护 catalog.json；完成实现、验证、push 与市场安装验证。

- 扫描 plugins/*/plugin.json，以 manifest 为插件及市场元数据唯一来源。author、category、platforms、minHostVersion 与 id/name/description/version/locales 保存在同一文件；删除 catalog.json。templates 不发布，非插件目录忽略，符号链接、重复 ID 和无效元数据拒绝。
- index.json 是客户端兼容的已发布索引，published.json 是发布收据，两者仍仅在 CI 验证所有附件后一起更新。保留串行发布、main SHA 校验、失败保留索引、不降级和不可覆盖同版本附件的保护。
- 新增 OCR 源码、模型、许可证及独立锁定构建依赖，最低宿主版本 0.2.30。使用已有识别实现，不重做 UI 或引擎；计算权限、取消、剪贴板保护保持一致。
- 打包容量匹配宿主：单文件 32 MiB，解压总量 128 MiB，压缩包 64 MiB。所有插件都走自动发现和既有构建/发布链；OCR 特殊 Vite 构建与 Ctool 一样由插件构建器接入。
- 迁移导致包内容变化的现有插件升级 patch 版本，旧 Release 不覆盖。OCR 使用 1.0.1，区别于宿主 v0.2.30 附件中的 1.0.0。
- 不改变宿主市场 URL 或客户端索引格式，不替换用户已安装应用。不增加手工上架审批。源目录删除后新索引移除该插件，保留历史发布附件和已安装数据。

压力测试：无效/重复 manifest 必须让 CI 失败而不能生成部分索引；缺失或过期构建失败；模板不能被收录；新增有效插件仅放目录即可进入候选；每个发布文件先验证再写索引；重新构建同版本复用已验证附件。现有 SDK 本地改动与远端相同，已通过 stash/快进/恢复保留后同步。
