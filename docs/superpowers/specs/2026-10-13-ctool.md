# Ctool 完整功能集成

用户于 2026-10-13 批准完整功能范围，包括联网工具。集成 baiy/Ctool 2.4.0，固定上游 commit `4f9255f7caa1049786c98a28fbd7bdcc1aef17dd`，保留 MIT 许可证及来源；复用 Vue 界面、工具算法、分类、搜索、历史和设置，不重写成缩水工具集。

## 实现边界

- 在 Nexlet-plugins 新增 `plugins/ctool`，独立的 `integrations/ctool` 保存适配和构建逻辑，`vendor/ctool` 保存可校验的上游源码快照。构建锁定依赖，输出 `.build/plugins/ctool` 和 `dist/ctool.nexlet`。
- 插件使用现有 backend、files、clipboard 和 shell API；最低宿主版本必须包含这些 SDK 能力，不以旧版可用为前提。保留宿主页面隔离，不开放 renderer 任意联网或 Node。
- 原有同步存储由启动前加载的缓存和有序持久化适配，错误可见；JDoodle 凭据使用 secrets，避免普通历史/设置明文保存凭据。
- HTTP 使用后台请求桥接，保留状态、headers、响应正文及错误；WebSocket 支持 ws/wss、子协议、发送、接收、断开和重连，退出清理连接。联网仅在原功能触发时执行，不产生安装后的无关自动请求。
- 原有文件输入、结果下载、图片复制、Monaco 与工具 Worker 必须实际可用。资产随包分发，检查大小及 CSP 兼容性。
- 提供 Ctool 总入口及不超过 30 个常用/分类入口，插件内部保留全部工具和子功能。文本激活导航到对应工具，重复激活不得丢失新输入。
- IP 查询、ARM/HEX 转换和 JDoodle 在线执行保留；第三方服务不可用时显示真实错误，JDoodle 需要用户填写凭据，不把 fixture 验证声称为真实服务执行。

## 验收

与上游配置逐项比对工具/路由数量，无隐藏或删减工具；真实宿主导入实际安装包，遍历页面，检查 Worker/动态资源/控制台错误，验证代表性的离线计算、文件读写、图片复制、重复进入、持久化、分离窗口。联网用受控本地 HTTP/WebSocket 服务检查真实桥接及失败场景，并单独记录公开服务实网探测结果。未授权 commit、push、市场发布或替换日常安装。
