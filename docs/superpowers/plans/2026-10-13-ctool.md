# Ctool 实施计划

依据同日已批准 spec，在当前会话执行，保留两个仓库所有已有改动。

1. **固定上游和构建**：新增 `vendor/ctool/{source.tar.gz,upstream.json,LICENSE}`、`integrations/ctool/build.mjs`，复用上游 pnpm lock；构建缓存放 `.build`。产物完整性、文件数、单文件/总大小符合宿主限制。必要时仅添加同源本地 Worker 所需兼容修复，不放宽网络权限。
2. **平台适配**：新增 `integrations/ctool/adapter`，接入平台运行时、启动和再次激活、持久化、clipboard、files 与 secrets；保持上游算法和工具定义。为存储有序写入、数据恢复和激活参数添加针对性测试。
3. **完整联网**：新增 `integrations/ctool/backend.mjs`，实现 HTTP、二进制和 WebSocket 桥接。测试 GET/POST、query、HTTP 错误、超时、连接建立/收发/子协议/关闭/退出清理；使用本地 fixture，不依赖公网服务稳定性。
4. **打包和文档**：新增 `plugins/ctool/plugin.json`、来源说明与构建入口，接入已有 scripts 时只追加本次范围。未发布包不写虚假市场下载链接；生成可导入包并记录最低宿主能力。
5. **验收**：`node --test tests/ctool*.test.mjs`、`npm run build:ctool`、`npm run package:ctool`、`node tests/ctool.e2e.mjs`，以及仓库现有 `npm test`、类型检查、`git diff --check`。构建/打包生成 `.build`、`dist`；首次依赖安装访问 registry，实网验证明确单列。E2E 使用临时用户数据和剪贴板 mock，不改日常数据。

## 风险与回滚

Monaco 体积、Worker、自定义协议、同步 storage 与异步 SDK 是主要兼容点；必须以构建和真实宿主验证为准。JDoodle/ARM 等第三方服务的账户、额度及在线状态不由插件保证。回滚只移除本次新增插件/适配/构建接入和本次必要宿主修复，不能覆盖已有 SDK 等并行改动。发布、提交和安装到日常用户配置仍需对应授权。
